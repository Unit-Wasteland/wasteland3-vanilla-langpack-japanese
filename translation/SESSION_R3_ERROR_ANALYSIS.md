## 根本原因

### 1. 誤った引用符フォーマット

**誤った変換:**
```
ソース:  string data = ""Japanese text""
↓ (誤った変換)
ターゲット: string data = "「Japanese text」"
```

**問題点:**
- Unity StringTableは`"`の数を厳密にチェック
- 日本語括弧`「」`は引用符としてカウントされない
- 結果: 引用符数不一致 (ソース=4, ターゲット=2)

### 2. 翻訳時の誤解

**誤った理解:**
> 「日本語では、セリフは日本語括弧「」で囲むべきだ」

**正しい理解:**
> 「Unity StringTableのセリフは、**常に引用符`""`で囲む**。日本語括弧は使用禁止。」

### 3. 構造マーカーとテキスト内容の混同

- **構造マーカー `""`**: 必ず保持（Unity format requirement）
- **テキスト内の引用**: 翻訳時に日本語括弧に変換可能

### 例:

**正しい変換例 1 (セリフ全体):**
```
ソース: string data = ""Tell me. What is the prayer?""
ターゲット: string data = ""教えてくれ。我々が捧げる祈りとは？""
                          ↑↑                        ↑↑
                          必ず" "を保持
```

**正しい変換例 2 (テキスト内の引用符):**
```
ソース: string data = " "VANDENBERG HALL" is etched"
ターゲット: string data = " "VANDENBERG HALL"と刻まれている"
                          ↑↑                ↑↑
                          テキスト内の引用符も保持
```

## 学んだ教訓

### 1. 効率 vs 正確性
- ❌ **誤り**: 効率重視で一括処理を試みる
- ✅ **正解**: 正確性重視で1つずつ処理

### 2. エラー修正時のルール遵守
- エラー修正中は、通常作業以上に厳格なルールが必要
- ERROR_FIX_RULES.mdの作成は正しい判断

### 3. 構造マーカーの理解
- Unity StringTableの`""`は **構造要素** であり、**テキスト要素ではない**
- 構造要素は **絶対に変更してはいけない**
